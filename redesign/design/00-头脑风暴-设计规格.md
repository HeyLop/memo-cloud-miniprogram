## 2. 产品定义

**一句话**：一个能"想到就记、到点必达、工作生活两不扰"的个人待办小程序。

**目标用户**：本人（单人使用），重度记录、怕漏事、工作与个人事务混杂。

**四层闭环**（D3 拆解）：

```
极速记录 → 工作生活分区 → 今日聚焦 → 可靠提醒
 (输入)       (组织)         (呈现)       (输出)
```

- **极速记录**：首页常驻输入框，一句话录入，**云函数 NLP 解析**（D7）自动抽取时间与分类。输入"明天下午3点交报告"→ 解析出 dueAt=明天15:00、zone=工作、title=交报告。目标 3 秒完成一条记录。解析失败时降级为手工补选时间（不丢数据）。
- **工作生活分区**：两条独立时间线/视图，**双色主题**（D9：工作=蓝色系、生活=暖色系），切换时导航栏/背景/强调色整体变化。各自的通知时段不同（D8）。
- **今日聚焦**：首页只显示今天该做的少数几件事，自动按优先级+截止时间排序，其余折叠。分区视图下各自聚焦本区。
- **可靠提醒**：微信订阅消息推送，**分区分时段 + 两级提醒**（D8）：工作事项只在工作时段推、生活事项在晚间/周末推；每类提前 1 天 + 到期各一次。`remindSent` 记录防重复。

## 3. 技术方案（基于 D5）

**平台**：微信小程序（微信云开发）

| 能力 | 方案 | 说明 |
|---|---|---|
| 数据存储 | 云开发数据库（文档型） | 替代原 PostgreSQL；集合：`todos`、`users` |
| 登录 | 微信云开发自带 openid 鉴权 | 无需 WorkBuddy OAuth；`wx.cloud` 调用天然带身份 |
| 定时触发 | 云函数定时触发器 | 每分钟扫描到期任务，调订阅消息接口发送 |
| 消息推送 | 微信订阅消息 | 用户授权后，云函数调 `subscribeMessage.send` |
| 前端 | 原生小程序（WXML/WXSS/JS） | 沿用原生路线，不上框架 |

**关键技术决策**：

- 放弃 WorkBuddy 云（含原有 notes 表、OAuth、应用卡发布链路），后端全换微信云开发。
- 云函数负责：定时扫描、消息发送、时间解析（可选）、用户身份映射。
- 前端只做展示与交互，不碰任何服务端凭证。

## 4. 数据模型（初稿）

`users` 集合：
```
{ _openid, createdAt, settings: { workHours, reminderLeadTime } }
```

`todos` 集合：
```
{
  _openid,            // 云开发自动注入，数据隔离
  title,              // 事项内容
  content,            // 备注
  zone: 'work'|'life',// 工作/生活分区
  priority: 'high'|'normal'|'low',
  dueAt: Date,        // 截止时间
  done: Boolean,
  remindLead: Number, // 提前提醒分钟数
  remindSent: [],     // 已发提醒记录，防重复推送
  createdAt, updatedAt
}
```

## 7. 三项决策的实现规格（已确认，供实施计划直接使用）

### 7.1 智能解析（D7）

- **触发**：首页输入框提交一句话 → 调用云函数 `parseTodo`。
- **云函数职责**：从文本中抽取 `dueAt`（时间）、`zone`（工作/生活）、`title`（去掉时间词后的事项）。
  - 时间解析：优先用 NLP 能力；若接第三方 API，凭证存云函数环境变量，不下发前端。
  - 兜底：解析失败或置信度低 → 返回 `needsManual: true`，前端弹出时间选择器让用户补选，原文保留为 title。
- **输出**：`{ title, dueAt, zone, confidence, needsManual }`。
- **前端**：解析结果先以"草稿卡片"展示，用户确认/微调后才入库——避免解析错误直接写脏数据。
- **验收**：输入"明天下午3点交报告"能在草稿卡显示正确时间与"工作"分区；输入无法解析的文本时能降级手工补选且不丢字。

### 7.2 提醒策略（D8）

- **两级**：每条待办最多两次推送——`dueAt - 1天`（提前提醒）与 `dueAt`（到期提醒）。
- **分时段**：
  - 工作区（zone=work）：仅在工作时段推送，默认工作日 09:00-18:00；非工作时段到期的，改到下一工作日 09:00 推。
  - 生活区（zone=life）：仅在晚间/周末推送，默认工作日 18:00-22:00 + 周末全天。
  - 时段参数存 `users.settings.workHours`，用户可配置。
- **防重复**：`todos.remindSent` 记录已发的 `{stage, sentAt}`，云函数发送前检查，同一 stage 只发一次。
- **订阅授权**：首次保存带时间的待办时请求订阅消息授权；未授权则只做 App 内提醒，不阻断其他功能。
- **云函数定时**：每分钟扫描 `dueAt` 落在推送窗口内的未完成待办，按规则发送。
- **验收**：造一条工作区明天到期的待办，提前提醒只在工作时段发出；同一条不会重复收到第二次。

### 7.3 界面风格（D9）

- **双色主题**：
  - 工作区：蓝色系（主色 #1769E0，背景 #F5F8FF）
  - 生活区：暖色系（主色 #D9730D，背景 #FFF8F0）
- **切换联动**：切换分区视图时，导航栏、页面背景、按钮、徽章、强调色整体切换；用 CSS 变量统一定义两套主题 token，页面只引用变量。
- **结构**：顶部分区切换（工作/生活）→ 今日聚焦卡 → 待办列表 → 底部极速输入栏。
- **验收**：切换分区时全页面配色随之改变；两区同一套组件，仅主题变量不同。
