## 2. 产品定义

**一句话**：一个能"想到就记、到点必达、工作生活两不扰"的个人待办小程序。

**目标用户**：本人（单人使用），重度记录、怕漏事、工作与个人事务混杂。

**四层闭环**（D3 拆解）：

```
极速记录 → 工作生活分区 → 今日聚焦 → 可靠提醒
 (输入)       (组织)         (呈现)       (输出)
```

- **极速记录**：首页常驻输入框，一句话录入，自动解析时间（如"明天下午3点交报告"）和分类。目标 3 秒完成一条记录。
- **工作生活分区**：两条独立时间线/视图，各自的通知策略不同（工作时间提醒 vs 生活提醒分时段）。
- **今日聚焦**：首页只显示今天该做的少数几件事，自动按优先级+截止时间排序，其余折叠。
- **可靠提醒**：微信订阅消息到点推送；支持多轮提醒（到期前+到期时）；漏推可手动补发。

## 3. 技术方案（基于 D5）

**平台**：微信小程序（微信云开发）

| 能力 | 方案 | 说明 |
|---|---|---|
| 数据存储 | 云开发数据库（文档型） | 替代原 PostgreSQL；集合：`todos`、`users` |
| 登录 | 微信云开发自带 openid 鉴权 | 无需 WorkBuddy OAuth；`wx.cloud` 调用天然带身份 |
| 定时触发 | 云函数定时触发器 | 每分钟扫描到期任务，调订阅消息接口发送 |
| 消息推送 | 微信订阅消息 | 用户授权后，云函数调 `subscribeMessage.send` |
| 前端 | 原生小程序（WXML/WXSS/JS） | 沿用原生路线，不上框架 |

**关键技术决策**：

- 放弃 WorkBuddy 云（含原有 notes 表、OAuth、应用卡发布链路），后端全换微信云开发。
- 云函数负责：定时扫描、消息发送、时间解析（可选）、用户身份映射。
- 前端只做展示与交互，不碰任何服务端凭证。

## 4. 数据模型（初稿）

`users` 集合：
```
{ _openid, createdAt, settings: { workHours, reminderLeadTime } }
```

`todos` 集合：
```
{
  _openid,            // 云开发自动注入，数据隔离
  title,              // 事项内容
  content,            // 备注
  zone: 'work'|'life',// 工作/生活分区
  priority: 'high'|'normal'|'low',
  dueAt: Date,        // 截止时间
  done: Boolean,
  remindLead: Number, // 提前提醒分钟数
  remindSent: [],     // 已发提醒记录，防重复推送
  createdAt, updatedAt
}
```

## 6. 明确不做（防止范围蔓延）

- ❌ 多人协作/共享（D2 已定为单人）
- ❌ iCloud/CloudKit（生态封闭）
- ❌ 跨端（H5/App），只做微信
- ❌ 富文本/附件/图片
- ❌ 自定义分类体系（工作/生活两分区固定）
