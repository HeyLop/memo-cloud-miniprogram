# 清单备忘 · 需求分析

> 版本 v1.1 · 2026-11-25

## 1. 项目背景

目标是做一个自己长期用的**备忘录 + 工作提醒**微信小程序。它从一个"跑通全流程"的最小 demo 演进而来，现在定位为正式产品：手机上随手记、到点前能看到该做的事、能把某条备忘发给别人看。

技术载体：原生微信小程序 + WorkBuddy 云服务（PostgreSQL 数据库 + 账号体系）。数据存云端，跨设备可见。

## 2. 目标用户与核心场景

| 用户 | 场景 | 诉求 |
|---|---|---|
| 本人（主用户） | 工作/个人/学习各类待办混杂 | 打开就看到今天该做什么，不用在一堆记录里翻 |
| 分享接收方 | 收到同事/家人发来的备忘 | 无需注册，凭一串码就能看到内容 |

暂不为接收方设计账号、编辑、协作功能（见"范围边界"）。

## 3. 功能需求

需求编号规则 `FR-x.y`，后续每次改动引用编号，便于追溯。

### FR-1 账号与登录

- **FR-1.1 微信一键登录（主路径）**：用户点「微信一键登录」，通过 `wx.login` 拿 code，换云端 session。验收：真机点击后进入备忘列表，刷新后仍保持登录。
- **FR-1.2 WorkBuddy 账号登录（备用路径）**：微信登录不可用时的降级入口，页面以次级文字链呈现。验收：点击跳转官方小程序授权后能回到本小程序并登录。
- **FR-1.3 会话持久化与登录门禁**：未登录只见登录页，已登录直接见数据；未登录不得读取云端数据。验收：退出登录后列表清空；重新打开保持上次状态。
- **FR-1.4 AppID 运行时获取**：微信登录传的 appid 必须取 `wx.getAccountInfoSync().miniProgram.appId`，不得硬编码。验收：试用版与正式版用各自 AppID 均可登录。

### FR-2 备忘管理

- **FR-2.1 新建**：字段含标题（必填）、正文、分类、优先级、截止时间。验收：标题为空时提示且不保存；保存后列表立即可见。
- **FR-2.2 编辑**：点击任一备忘进入编辑页，预填原值，可修改保存。验收：修改后列表同步更新。
- **FR-2.3 删除**：二次确认后删除，提示不可恢复。验收：确认删除后列表不再显示。
- **FR-2.4 完成勾选**：一键切换完成状态。验收：已完成的标题加删除线、置灰，今日提醒区不再出现。
- **FR-2.5 分类**：固定四类「工作/个人/学习/其他」，默认「工作」。验收：编辑页可选，首页可按类筛选。
- **FR-2.6 优先级**：固定三档「高/普通/低」，默认「普通」，列表用颜色徽章区分。验收：高=红、普通=灰、低=绿。
- **FR-2.7 云端持久化与隔离**：所有数据存云端 `notes` 表，按用户隔离，换设备登录数据仍在。验收：A 用户看不到 B 用户的备忘。

### FR-3 今日提醒

- **FR-3.1 今日提醒区**：首页顶部聚合"今天到期或已逾期"且未完成的备忘，逾期/到期项高亮。验收：设一条今天到期的备忘，首页顶部可见；把它标记完成后消失。
- **FR-3.2 订阅授权采集**：保存带截止时间的备忘时请求微信订阅消息授权。验收：保存含时间的备忘会弹授权框（在模板 ID 已配置的前提下）。
- **FR-3.3 主动推送（未实现，见限制）**：到点由微信推送通知。当前代码只预留模板 ID 配置位，缺少定时触发能力，**不计入 v1 验收**。

### FR-4 分享

- **FR-4.1 生成分享码**：对任一备忘生成 10 位随机码，写入 `notes_share` 表，原备忘记录 token。验收：点分享弹窗显示码，可一键复制。
- **FR-4.2 凭码查看**：接收方在「共享备忘」页输入码，只读查看内容。验收：正确码显示内容，错误码提示"不存在或已失效"。
- **FR-4.3 快照语义**：分享是生成时点的只读副本；原备忘后来修改，分享内容不自动更新，需重新分享。验收：改原备忘后，对方的分享页内容不变。

## 4. 非功能需求

| 编号 | 类别 | 要求 | 验收方式 |
|---|---|---|---|
| NFR-1 | 数据安全 | 数据库开启 RLS，用户只能读写自己的数据；分享表仅凭 token 可读 | SQL 策略核查 + 跨账号验证 |
| NFR-2 | 编译兼容 | WXSS/WXML 选择器与 class 名一律 ASCII，中文只出现在文本和数据值 | 全量扫描无中文选择器 |
| NFR-3 | 可构建 | 所有 JS 通过 `node --check`，所有 JSON 严格合法 | 本地校验脚本 |
| NFR-4 | 可追溯 | 每次发布对应 git commit，文档与代码同步更新 | git log + 本文档版本 |
| NFR-5 | 真机可达 | 最终需在手机微信试用/正式版验证登录与云端读写（H5 预览不算） | 真机走一遍核心链路 |

## 5. 范围边界（明确不做）

写下来是为了防止下次"顺手就加了"，导致范围和架构失控：

- ❌ **实时协作**：多人同时编辑同一份备忘（v1 只做只读快照分享）
- ❌ **iCloud / CloudKit 同步**：生态封闭且小程序无法调用，已排除
- ❌ **微信主动定时推送**：当前云服务无定时触发/消息接口，v1 只做 App 内提醒 + 授权采集
- ❌ **富文本 / 附件 / 图片**：正文为纯文本
- ❌ **用户自定义分类 / 标签体系**：固定四类，不做动态管理
- ❌ **离线编辑同步**：依赖网络，无本地队列
