# 清单备忘 · 待办与已知限制

> 版本 v1.1 · 2026-11-25
> 这是"下一步从哪开始"的入口。每项标注阻塞原因和前置条件，避免立即开干却卡死。

## 1. 已知限制（当前版本的真实边界）

| 限制 | 影响 | 根因 | 能否在代码内解决 |
|---|---|---|---|
| 微信主动推送未实现 | 不打开小程序就收不到提醒 | 云服务无定时触发/消息接口 | ❌ 需平台能力或云函数 |
| 分享是只读快照 | 原备忘更新后对方看到的是旧内容 | 快照模型设计如此（ADR-005） | ✅ 但需改模型，非 bug |
| 真机登录未验证 | 微信登录/云端读写尚未在手机微信跑通 | H5 预览拿不到真实 code | ❌ 需真机 |
| 微信登录依赖后台配置 | 未绑定小程序/未开开关时登录失败 | 应用后台配置项 | ❌ 需后台操作 |
| 本机开发者工具不可用 | 无法走 IDE 真机调试 | NW.js 运行时不兼容 | ⚠️ 可升级工具，非必须 |

## 2. 待办清单

按优先级排序。`P0` = 阻塞核心体验，`P1` = 重要，`P2` = 增强。

### P0 · 真机端到端验证

- [ ] 发布试用版，手机微信扫码打开
- [ ] 验证微信一键登录（需先完成后台绑定 + 开关，见下）
- [ ] 验证登录 → 新建备忘（带截止时间）→ 换设备登录数据仍在
- [ ] 验证分享码：生成 → 另一台设备/他人输入码 → 只读查看

### P0 · 微信登录后台配置（用户侧操作，代码替代不了）

- [ ] 应用后台完成小程序绑定（试用/正式各一套）
- [ ] 开启 `wechat_login_enabled` 开关
- [ ] 真机确认 `wx.getAccountInfoSync().miniProgram.appId` 取到正确 AppID

### P1 · 微信订阅消息推送（受平台能力阻塞）

- [ ] 微信公众平台申请订阅消息模板，把模板 ID 填入 `utils/config.js` 的 `SUBSCRIBE_TEMPLATE_IDS`
- [ ] 评估定时触发方案：云服务是否提供定时/云函数；若无，是否引入外部定时服务
- [ ] 实现到点推送 + 推送后的落地页跳转

### P1 · 输入与体验

- [ ] 正文支持多行长文本优化（当前 textarea 高度固定）
- [ ] 删除备忘时一并处理其分享快照（当前 `notes_share` 记录不会自动清理）
- [ ] 时间冲突/逾期更明显的视觉区分

### P2 · 共享增强

- [ ] 分享码增加有效期 / 可撤销
- [ ] 分享内容随原备忘更新的机制（需重构 ADR-005 的快照模型）
- [ ] 分享时可选择是否包含正文

### P2 · 工程化

- [ ] 本地校验脚本化：一键跑 JSON/JS/WXSS 中文选择器扫描
- [ ] CI：push 到 GitHub 自动跑校验
- [ ] README 补充真机调试/发布的操作截图

## 3. 下一步建议路径

不要同时开多条线。建议按这个顺序：

1. **先完成 P0 真机验证**——这是唯一能证明"产品真的能用"的环节，其他都是纸上谈兵。任何登录/数据问题先在这里暴露。
2. 真机通过后再做 P1 的体验优化和推送评估（推送受平台能力阻塞，不要一头扎进去）。
3. P2 按需做，特别是共享增强要靠需求验证是否真有人用，别过早投入。

## 4. 交接须知（给下一次接手的自己/协作者）

- 改需求 → 先改 `01-需求分析.md`（含验收标准和变更记录）
- 改架构 → 先改 `02-技术设计.md`
- 想推翻已有方案 → 先读 `03-决策记录.md` 确认前提是否真的变了，并新增一条 ADR
- 每次实质改动 → 更新 `04-开发记录.md` 追加时间线
- 发布 → 对应一个 git commit，push 到 `HeyLop/memo-cloud-miniprogram`（非沙箱执行）
