# 清单备忘 · 决策记录（ADR）

> ADR = Architecture Decision Record。每条记录一个"当时为什么这么定"。
> 下次想推翻某个决定时，先读这里的理由，确认前提变了再改。

---

## ADR-001 采用原生微信小程序 + WorkBuddy 云服务

- **日期**：2026-11-24
- **状态**：已采纳
- **背景**：需要从 0 做一个能在手机微信打开、数据上云的小程序。可选原生 / Taro / uni-app。
- **决策**：原生 WXML/WXSS/JS，后端用 WorkBuddy 云服务（CloudBase + PostgreSQL）。
- **理由**：单端微信、追求最快跑通；WorkBuddy 提供脚手架 + 应用卡预览/发布闭环，省去自建后端和上传审核的繁琐。2026 年跨端框架性能差距已很小，但本项目没有多端需求，跨端是多余的复杂度。
- **被否决**：Taro / uni-app（无多端需求，增加工程复杂度）；自建服务器（ workbuddy 云服务已覆盖数据库/登录）。
- **代价**：锁在微信生态与 WorkBuddy 云平台上，迁移需重写。

## ADR-002 早期采用 WorkBuddy 账号登录，后改为微信为主、双轨保留

- **日期**：2026-11-25（当日变更）
- **状态**：已采纳（当前为双轨）
- **背景**：云服务身份体系基于 WorkBuddy 账号，RLS 的 `auth.uid()` 来自 WorkBuddy session。最初只有 WorkBuddy 登录能不依赖任何后台配置就跑通。用户后来问"为什么不是微信登录"。
- **决策**：主按钮改为微信一键登录（`signInWithWechat`），WorkBuddy 登录降级为备用文字链，两者都保留。
- **理由**：SDK 两种都支持，微信登录更符合用户直觉；但微信登录有硬前提（小程序绑定 + `wechat_login_enabled` 开关 + 运行时 appid），配置未就绪时会失败，故保留 WorkBuddy 作为可用降级。
- **被否决**：只保留 WorkBuddy（用户体验不符）；只保留微信（后台配置未就绪时完全无法登录）。
- **代价**：两条登录路径要维护；两者产出的是不同 provider 的 session，需注意(session 结构统一由 SDK 处理)。

## ADR-003 数据上云而非本地存储

- **日期**：2026-11-25
- **状态**：已采纳
- **背景**：最小 demo 阶段云服务授权被取消，一度用 `wx.setStorageSync` 本地存储跑通。用户重新授权后决定上云。
- **决策**：云端 `notes` 表 + RLS 行级隔离，登录门禁控制访问。
- **理由**：备忘的核心价值是跨设备可见；本地存储换设备即丢失，且无法做分享。
- **被否决**：本地存储（无法跨设备/分享）；iCloud/CloudKit（生态封闭、安卓用户无 iCloud、小程序无法完成 Apple ID 授权、域名白名单受限——见 ADR-004）。
- **代价**：依赖网络；必须处理登录态与云端错误。

## ADR-004 明确排除 iCloud 作为共享方案

- **日期**：2026-11-25
- **状态**：已否决
- **背景**：用户问"小程序能用 iCloud 做共享吗"。
- **决策**：不用。
- **理由**：① iCloud 绑定 Apple ID，仅苹果设备间同步，微信用户大量为安卓；② CloudKit Web 需 Apple ID 登录拿 token，小程序内无法完成该授权流程；③ 请求域名白名单 + HTTPS 强制，CloudKit 域名需额外报备且受苹果策略变动影响。
- **替代**：用云数据库做跨设备同步（已实现）和分享（见 ADR-005）。

## ADR-005 共享采用"只读快照 + 分享码"，而非实时协作

- **日期**：2026-11-25
- **状态**：已采纳
- **背景**：用户要"共享给他人"。可选：实时协作共享文档 / 生成可转发的分享链接或码。
- **决策**：生成 10 位随机码，把备忘内容快照写入 `notes_share` 表，接收方凭码只读查看。
- **理由**：不需要知道接收方的用户 ID，实现最简单稳定；快照语义清晰，不产生并发冲突；RLS 可公开读该表。
- **被否决**：实时协作（需共享文档模型 + 权限授权机制 + 冲突处理，成本高且 v1 无此刚需）；分享整个账号数据（越权风险）。
- **代价**：原备忘更新后分享内容不自动变，需重新分享；无法控制接收方转发。

## ADR-006 微信主动推送暂缓，只做 App 内提醒

- **日期**：2026-11-25
- **状态**：部分实现（推送未实现）
- **背景**：用户选了"微信推送提醒"。
- **决策**：v1 实现 App 内今日提醒 + 订阅授权采集 + 模板 ID 配置位；到点主动推送不做。
- **理由**：当前 WorkBuddy 云服务只开放 Database/Auth/Storage/LLM，无定时触发器与消息推送接口。缺的是平台能力，不是代码能绕过的。
- **被否决**：轮询/长连接模拟（小程序后台不可靠且耗电）；假装已完成（ dishonest）。
- **代价**：用户不打开小程序就收不到提醒。后续需平台提供定时能力或接入云函数+订阅消息。

## ADR-007 WXSS 类名统一 ASCII

- **日期**：2026-11-25
- **状态**：已采纳（强制约定）
- **背景**：发布校验失败：`pages/index/index.wxss:265:11: unexpected \`?\` at pos 4173`。
- **决策**：所有选择器/class 名用 ASCII；中文值通过 JS 映射成 ASCII 类名。
- **理由**：微信编译器不接受非 ASCII 字符作 CSS 标识符，中文字节被当成非法 token。
- **实现**：`PRIORITY_CLASS` 映射，`高→priority-high` 等，`decorate()` 注入 `priorityClass` 供 WXML 绑定。
- **代价**：数据值到样式多一层映射；新增中文枚举值时必须同步加映射。
